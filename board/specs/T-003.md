# T-003 — ai-maestro cockpit: portfolio mode

**Owner decision, 2026-08-08.** There is one board tool, and it is `@mychiefmind/ai-maestro`.
Root `cockpit/` is deleted (kit-099). Anything it does that the package cannot must be
upstreamed into the package first — this document is that gap, measured file by file.

This supersedes `docs/architecture/portfolio-separation-plan.md:76-80`, which kept `cockpit/`
as a permanent shared surface on the reasoning that "the value of the cockpit is the
*portfolio* view." The value is real; the conclusion (keep a second console) is not. Portfolio
view becomes a mode of the one console.

## The two codebases

| | root `cockpit/` | `maestro/cockpit/` (vendored 0.1.22) |
|---|---|---|
| package | `lense-kit-cockpit` | `maestro-cockpit@0.2.0` |
| server | `server/index.mjs` 295, `server/boards.mjs` 213 | `server/index.mjs` 556, `dev.mjs` 62, `ports.mjs` 72, `sanitize.mjs` 99 |
| client | 2,473 LOC across `src/` + 8 components | 1,352 LOC across `src/` |
| **total** | **2,981** | **2,141** |
| scope | N boards via `projects.json` | one `BOARD_DIR` |
| runs as | launchd `com.mychiefmind.cockpit`, pinned :3017 | dev server, port-scans from 4600 |

The packaged cockpit is not a cut-down root cockpit. On the single-board surface it is **ahead** —
it has a specs editor (`PUT /api/spec/:id`), `RosterPage`, `CheatSheet`, `WelcomeModal`, and
config-driven plan steps, none of which root has. The gap is entirely about *breadth*.

## Capability diff

### 1. Registry + allowlist — MUST UPSTREAM

Root: `cockpit/server/boards.mjs:26-59` reads `projects.json`, throws loudly if it is missing or
malformed (a silent empty registry would render as "no work on the boards"), and derives `BOARDS`
from it. The registry **is** the write allowlist — the UI never supplies a path.

Package: no registry concept. `resolveBoardDir()` (`index.mjs:94-108`) takes `--board`/cwd and
`isInsideKit()` (`index.mjs:80`) confines every path to the kit root.

Generalise: `isInsideKit` becomes "inside a registry-listed project root". Keep the throw-loud
behaviour — it is the difference between "the registry did not load" and "there is no work".

### 2. Multi-board read-across — MUST UPSTREAM

Root: `readBoards()` (`boards.mjs:112`) maps every registry scope through `readBoard()`;
`GET /api/boards` (`index.mjs:212`) serves them together. `DONE_STATUSES` (`boards.mjs:67`) is
`{done, merged, archived}`.

Package: `GET /api/board` (`index.mjs:229`) — singular, one file.

This is the one thing the packaged cockpit *structurally* cannot do today, and the reason the
plan originally kept root cockpit alive.

### 3. Survey / `/today` — MUST UPSTREAM (board half only)

Root: `survey()` (`boards.mjs:141`) returns per-project ticket counts by status plus a
ready-to-run list gated by `ticketReady()` (`boards.mjs:118`), stamped with `isoWeek()`.

The **marketing half** of the same function (`boards.mjs:152-166` — ledger week, `byStatus`,
`needsApproval` queue) does *not* come here. It goes to social-ops with kit-098.

### 4. Multi-root docs portal — MUST UPSTREAM

Root: `DOC_ROOTS` (`index.mjs:76`) derived from every registry project carrying `docs`;
`DocsPortal.tsx` (296) renders a persistent two-pane portal across all of them;
`rewriteDocImages()` (`index.mjs:148`) resolves relative `<img>` to `/api/docs/raw`.

Package: `docSections()` (`index.mjs:406`) over one project; `DocsPage.tsx` (95); it already has
its own `rewriteDocImages` (`index.mjs:428`) and `/api/docs/asset`.

The rendering is solved on both sides. The gap is N roots vs one.

### 5. Report serving — MUST UPSTREAM

Root: `GET /reports/:name` (`index.mjs:185`) serves generated HTML reports in place.
Package: none.

### 6. Stable service mode — MUST UPSTREAM

Root is always-on: launchd `com.mychiefmind.cockpit` on a pinned :3017, fronted by the
dev-gateway at `https://cockpit.localhost`. `scripts/open-board.mjs` probes that port and prints
a `launchctl load` hint when it is down.

Package: `ports.mjs` scans from 4600 with a 20-port window — correct for a per-project dev
console, wrong for a service a launchd job and an nginx vhost both need to find. Needs a pinned
service entrypoint.

**Gateway gotcha when repointing:** `*.localhost` is a public-suffix wildcard and covers nothing.
`cockpit.localhost` must stay explicit in the mkcert SAN list or curl and headless clients fail
while browsers appear fine.

## Do not regress the hardening

The packaged cockpit has three protections root cockpit lacks entirely:

- `sanitize.mjs` (99 LOC)
- `isInsideKit()` path containment (`index.mjs:80`)
- `LOCAL_HOSTS` header check (`index.mjs:201-224`) — rejects non-local `Host` headers

Portfolio mode widens what paths are legal. It must not widen *whether paths are checked*. Root
cockpit's looseness is not a precedent to carry upstream.
